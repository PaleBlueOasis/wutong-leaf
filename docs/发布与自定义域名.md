## 让别人访问

2026-10-30 检查此项目的能力，支持 `custom`（指定访问者）与 `public`（任何知道网址的人）。用户明确要求公开时，通过 Sites 更新访问权限为 `public`。不必重新建站，也不必把源码仓库设为公开。

公开后，访客无需登录即可体验。探索、收藏和偏好保存在当前浏览器；账号和云端档案暂缓。配置密钥并同意后，访客可在网站共享额度内使用 AI。私有托管时，平台可能要求所有者身份，这是发布访问控制，不是本产品的登录功能。

## 不带 chatgpt.site 的网址

Sites 提供自定义域名能力，无需迁移当前代码和服务端接口。

1. 用户拥有一个域名，并决定完整主机名，例如 `www.example.com` 或 `walk.example.com`。这些仅为格式示例，不表示已替你注册。
2. 先将网站发布成功，再为同一个 Site 添加该主机名。
3. Sites 会返回准确的 DNS 目标及验证记录。子域名通常使用返回的 CNAME；根域名使用返回的 A 记录。**不要自己猜 IP 地址或把默认网址直接当成 DNS 目标。**
4. 在域名服务商的 DNS 控制台填入所有返回的记录，保留与其他服务有关的既有记录。
5. 刷新域名验证，确认域名状态与 HTTPS/SSL 状态均就绪，再测试访问和核心交互。

域名绑定不会自动把私有站设为公开。如需任何人访问，还要单独设置公开权限。`www` 与根域名是不同主机名；需要两个都能访问时，分别配置或使用服务商支持的跳转。

尚未购买、绑定或验证任何自定义域名。具体 DNS 值需在用户提供自己拥有的主机名后，由 Sites 实际返回。
